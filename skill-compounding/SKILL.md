# 沉淀复用:三次规则

**同一个问题第三次出现,就必须沉淀。** 归档不是目的,让下一次交付从第 3 天变成第 3 小时才是。

## 升级路径

| 情况 | 动作 |
|---|---|
| 只此一次 | 留 README:是什么、怎么跑、注意什么 |
| 同类第二次 | 抽参数做成可配置脚本,别人改配置就能用 |
| 第三次 | 沉淀为 skill / 内部工具,**带上前两次的教训** |

## 沉淀模板

```
解决了什么问题:一句话(带场景)
怎么用:三条命令以内跑起来
踩过的坑:①__ ②__(新人必看)
下次直接改哪里:__
```

## 执行规则

1. 沉淀物必须**可独立运行**,不依赖"来问我"
2. 教训比功能更值钱——失败记录必须写进去
3. 每次复用后回来更新一次(哪里卡了、哪里过时了)
4. 判断沉淀价值的唯一标准:**下一次有没有真的变快**
