# AI 协作交付循环

**起手式是和 AI 一起想,不是让 AI 直接写。**

## 起手三动作

1. 让 AI **复述**它对方案的理解——理解错了这里就能拦住
2. 让 AI 列出它认为的**风险和未知**——比让它直接写代码值钱
3. 指令四要素:背景 + 任务 + 要求 + 格式

## 交付顺序(固定,不跳步)

```
① 跑通最小闭环 → ② 补错误处理与日志 → ③ 补测试(主路径+边界) → ④ 部署
```

每完成一块,**让 AI 自己 review 一遍**再交人验收——判断力是人的,体力活是 AI 的。

## 分类型检查清单

| 类型 | 必答问题 |
|---|---|
| 运营自动化工具 | 人工干预点在哪?出错找谁? |
| 定时脚本 | 失败重试?重复执行幂等?谁收到失败通知? |
| 对话 Agent / 飞书企微 bot | 答不上来怎么兜底?敏感操作要不要人工确认? |
| 数据流水线 | 脏数据去向?断点续跑?对账怎么验? |

## 验收纪律

- 不看 AI 说"完成",看**可复现证据**:测试跑过、日志干净、演示给使用方
- AI 的"成功"输出 ≠ 真成功——查证据链(日志/测试/产物),不查表象
