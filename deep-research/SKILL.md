# 理性网络研究:五步规程

搜索谁都会,研究有纪律。本规程的产出标准:**每条结论可溯源,每个来源可评级,事实与观点分离**。

## 第一步:问题分解(动笔前)

把主问题拆成 3-6 个子问题,每个子问题独立可搜索:
- 主问题"X 是否值得引入" → 子问题:它解决什么痛点 / 现有替代品 / 维护状态 / 迁移成本 / 已知的坑
- 子问题写进研究计划,**先给主人过目再开搜**(避免搜偏)

## 第二步:多路检索(至少三路)

| 路 | 工具 | 查什么 |
|---|---|---|
| 官方路 | 项目 GitHub/API 文档 | README、releases、CHANGELOG——一手事实 |
| 权威路 | 站内搜索 + 权威媒体 | 评测、对比、事故记录——二手但可信 |
| 社区路 | 论坛/issue 区 | 真实用户的坑——噪音多,只取反复出现的 |

规则:每路至少 2 个独立来源;**单一来源的结论必须标注"单一来源"**。

## 第三步:来源评级(每条信息标级)

| 级 | 来源 | 使用规则 |
|---|---|---|
| A | 官方文档/官方公告/源码 | 可作事实直接引用 |
| B | 权威媒体/多篇独立一致 | 可作事实,标注日期 |
| C | 单一社区帖/博客 | 只作线索,须 A/B 级复核后才能进结论 |
| D | 匿名/AI 生成/营销号 | 不进结论,最多当提示 |

数字、人名、日期:**一律回 A 级来源核一遍再写**。

## 第四步:交叉验证(结论的纪律)

1. 事实/推测/观点分离——写报告时分段标注
2. 不同意主流说法 → 直接写不同意 + 依据 + 风险 + 替代解释
3. 发现自己之前的结论错了 → 当场更正,注明错在哪(前后对照)
4. 主动写"被忽略的变量/成本/偏差"一节

## 第五步:产出(带引用的报告)

```
# 研究报告: <主问题>
## 结论(先说答案: 直接用 / 改造 / 自研 / 或事实性判断)
## 证据表(每行: 结论 | 来源 | 级别 | 日期)
## 风险与被忽略的变量
## 来源清单(全链接)
```

## 工具

`fetch_source.py <URL>`:抓取网页转纯文本(自动去脚本/样式),供引用定位——本目录下。

## 纪律红线

- 反锁定:重要结论**不依赖单一信息源、单一供应商**(两个视频的共同核心)
- 撞同一堵墙两次 → 换路(问主人/换来源/换工具),不硬凿
- 查不到就写"查不到+已试过的路",**不编造**
